# Mock experiments (2026-10-14): what they would show, before deciding to run them

**Every number in this file is FAKE.** These are predictions of plausible outcomes, written to judge whether each
experiment is worth running and how it would read in the paper. Nothing here has been run. Do not copy any number into
the manuscript.

## M1. Placing the audit's evasion next to the region prior work already documents (AU)

**The criticism it answers.** A reviewer who knows that MalConv is sensitive to the DOS header (Demetrio et al.) will
read "12.4% evasion" and ask how it compares with what is already known, and whether the audit found anything new.

**Two ways to answer.**
- *Text only (no experiment).* Say that the audit measures reliance with unoptimized, loader-safe changes (random or
  benign-typical values, no queries), which is a different quantity from an optimized attack's success rate; and that
  every confirmed field lies outside the DOS header, so the audit finds reliance beyond the documented region. This
  costs nothing and may be enough.
- *A reference row (small experiment).* Apply the same unoptimized, loader-safe treatment to the DOS-header region that
  prior work identified, on the same 902 files, so the two regions are compared under identical rules. One more recipe
  in `scripts/audit_evade.py`; minutes to run. No optimization against the model, no retraining.

**What it would add.** Under identical, unoptimized rules, the audit's fields would sit next to the documented region
rather than next to published attack success rates measured under different rules. It does *not* make the audit an
attack paper, and it does not need any query-based optimization (which would add a lot of complexity for little gain).

**Mock table (FAKE).**

| changed region (loader-safe, unoptimized) | fields | evasion, 902 detected held-out malware |
|---|---|---|
| pushforward-confirmed fields | 7.3 | 12.4% (real, run 47) |
| surrogate-confirmed fields | 7.2 | 10.4% (real, run 47) |
| union | 11.2 | 18.4% (real, run 47) |
| DOS-header region documented in prior work | — | *9% (FAKE)* |
| pushforward fields + DOS region | — | *21% (FAKE)* |
| other loader-ignored fields outside the DOS region | 7.3 | 6.0% (real, run 49) |

**How it might read.** "Under the same rules, the audit's fields evade about as often as the region prior work
identified by hand, and the two add up: the audit finds reliance beyond what was known." If instead the DOS region
dominated (e.g., 30% fake), the paper would say the audit recovers a second, smaller lever, which is weaker but still
honest.

**Recommendation.** Start with the text-only answer; run the reference row only if, after the scale-up, the evasion
section still reads as unanchored. The mitigation (test-time zeroing, retraining) stays deferred, as decided.
